QuietCool ESPHome installer

Two paths: (1) replace OEM firmware with custom ESPHome via Web BLE (sections 1–6 below), or (2) open the local firmware page on a hub already running the ESPHome firmware (section at the bottom).

3. How will you authenticate?

The hub rejects every command except Login until a valid pair-id authenticates the session. Pick the path that matches your hub's current state — read this before connecting, because once this page grabs the BLE link, the QuietCool Smart Control app can't talk to the hub at the same time.

Once the QuietCool Smart Control app on Android or iOS pairs with a hub, the factory test ID stops working and the real pair-id isn't user-visible. This path side-steps that by putting the hub into pair mode so we can register a fresh ID.

Pick whichever is easier for you — both end with the hub advertising as pairable for ~tens of seconds:

Method A — physical button
  1. Find the Pair button (KEY2) on the hub. It's the same button used during initial setup.
  2. Press and hold it for 3 or more seconds, then release. LED4 (the pair LED) will change to indicate the hub is pairable.
  3. Come back here and press the Connect & flash button in step 6 below — quickly, the window is short.
Method B — Smart Control app
  1. On a phone with the QuietCool Smart Control app (available on Android and iOS — it needn't be the device running this installer), tap your hub, then tap Pair Mode.
  2. Wait until the app confirms pair mode is active.
  3. Force-close the OEM app (swipe it away in the recents view). The hub only allows one BLE central at a time — leaving the app open will block this page from connecting.
  4. Come back here and press the Connect & flash button in step 6 below.

When you press Connect & flash, this wizard will register a fresh random pair-id with the hub and save it in this browser so you can retry without re-running pair mode if anything goes wrong.

A factory-fresh hub accepts the OEM's built-in test pair-id with no button press — just keep the default below. This also works if you saved a pair-id from a previous run of this wizard in this browser.

Default 1234567dsad8wqw9asasd is the OEM's factory test ID — it stops working the first time the QuietCool Smart Control app on Android or iOS pairs with the hub.

Already running the ESPHome firmware?

Open the firmware page served by the hub itself. It can flash a compatible firmware URL or upload a locally saved OEM application .bin. Running the forms on the hub avoids browsers blocking an HTTPS installer from posting to a plain-HTTP LAN device.

No download is required to restore the known OEM V4.1. On the device page, click Use known OEM V4.1, then Download and flash URL; the hub downloads the verified image itself. The local-file form is the version-independent fallback if the vendor URL disappears.

Enter the mDNS name the device announces, or its LAN IP. A port is optional. Do not add a path.

How does this work? / troubleshooting

The button navigates directly to http://<host>/restore-stock. That page uses same-origin requests to the device's /api/flash_url and /api/restore_stock_file endpoints, shows upload progress, and disables its controls while a flash is active.

No auth on this endpoint by default — this is an intentional LAN-trust tradeoff. Home Assistant adoption secures ESPHome API/OTA but does not add web-server authentication. To protect these HTTP endpoints, add auth: { username, password } under web_server: in your build or adopted wrapper.

Common failure modes:

  • Page doesn't open → device hostname doesn't resolve; try the LAN IP instead. The full mDNS name is required, including the MAC suffix (e.g. quietcool-atticfan-abcdef.local, not just quietcool-atticfan).
  • "404 Not Found" → device firmware doesn't have web_server + http_flash_handler wired. Re-flash with a current build that includes them.
  • Update is rejected → the device page shows the endpoint's validation reason. Correct it there and retry.

Caveats

  • The OEM firmware does not verify signatures on OTA images — anything reachable at the firmware URL gets flashed. Only point this at images you trust.
  • If the hub has been paired with the QuietCool Smart Control app on Android or iOS, the factory test pair ID stops working — use the put it into pair mode option instead.
  • Wi-Fi password is transmitted in cleartext over BLE (an OEM trait, not ours). Acceptable for a one-shot bootstrap; BLE range is ~10 m.
  • If the host serving the firmware uses HTTPS, the hub trusts standard public CAs. If your cert isn't trusted, fall back to plain http://.
